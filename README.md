Agile BA Sprint Showcase

There is a lot of noise on the internet about what a Business Analyst does.
This project shows it.

A Dutch digital bank was losing one in three customers during identity verification. Not because the technology was broken. Because nobody had thought about the experience. The upload journey had been migrated from web to mobile in 2021 and left untouched since. No owner. No SLA. No feedback when something went wrong. Just a generic error message that sent 65% of people away for good.
This project documents everything a Business Analyst produces to fix that - from the moment the problem is defined to the point a development team can pick up the work and build without ambiguity.

The artifacts

01 - Business Problem Statement
The starting point. Defines the situation, what it is costing the business, the root cause (found through a structured 5 Whys analysis), and how success will be measured. Written before a single user story exists.

02 - Stakeholder Register
Six stakeholders. Each one mapped by power and interest, given an engagement strategy, and assigned clearly in a RACI matrix. Because the fastest way to sink a project is to manage the wrong people too closely - or the right people not closely enough.

03 - AS-IS Process Map
The current journey drawn in BPMN 2.0 across three swimlanes - Customer, System, and Compliance Team. Six failure points annotated in red, each with the data behind it. This is not a diagram for its own sake. It is a diagnosis.

04 - User Stories + Acceptance Criteria
Ten sprint-ready user stories with Given/When/Then acceptance criteria and a MoSCoW prioritisation. Written so that a developer reading them on a Monday morning knows exactly what to build and exactly when it is done.

05 - Jira Sprint Board
Sprint 1 set up and loaded. 
Must-Have stories committed, story-pointed, and in progress. This is what the work looks like inside the machine.

06 - TO-BE Process Map
The future state. Same three swimlanes, same BPMN notation - but the failure points are gone, replaced with six green improvement annotations. The retry loop replaces the dead end. The 4.2-day wait becomes a 24-hour SLA.

How this was built
Every artifact connects to a real sprint event. The problem statement existed before Sprint 0. The process maps came out of stakeholder interviews. The user stories were refined and sprint-ready before planning started. Nothing was produced for its own sake.

The root cause of the problem - a governance gap, not a technical failure was found through a 5 Whys analysis. That distinction mattered. It changed what the solution needed to be.
